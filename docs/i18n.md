# Frontend i18n (Lingui)

`apps/web` is translated with [Lingui](https://lingui.dev) 6. Source strings are written in
Chinese; the message id is the zh-CN text, so an untranslated message falls back to Chinese.
Languages: `zh-CN` (source) and `en`, listed in `apps/web/lingui.config.ts` and
`apps/web/app/lib/locale.ts`.

## Writing strings

```tsx
import { Trans, useLingui } from '@lingui/react/macro'

const { t } = useLingui()
<button aria-label={t`关闭`}><Trans>返回首页</Trans></button>
t({ message: '回复', context: 'button' }) // `context` tells apart same-looking messages
```

- Use named locals in placeholders (`const label = theme.label; t\`${label}\``), not member
  expressions, or the placeholder becomes `{0}`.
- Plurals use `<Plural>` / ICU `plural`; Chinese needs only `other`.
- Module-level constants cannot call `t` at load time: define them with `msg` from
  `@lingui/core/macro` and translate at render with `i18n._(label)`.
- Do not translate user content or API error text; have the API send codes and word them here.

## Workflow

```sh
pnpm --dir apps/web i18n:extract   # update app/locales/*.po from the source
# fill the empty msgstr in app/locales/en.po
pnpm --dir apps/web i18n:check     # extract --clean, then compile --strict (fails on missing en)
```

`.po` files are committed. The Lingui Vite plugin compiles them on import; there is no separate
compile step for the app.

## How a request is served

- `localeFromRequest` (`app/lib/locale.ts`): `forum_locale` cookie, else `Accept-Language`, else zh-CN.
- The root loader returns `locale` and the compiled `messages`; `Layout` builds a **per-render**
  `I18n` (`createI18n`) and wraps `children` in `I18nProvider`. Never use the global `i18n`
  singleton on the server: concurrent requests would leak languages.
- Production builds strip the source text from `t`/`<Trans>`, so a render without a catalog would
  show raw message ids. `createI18n` therefore defaults to the bundled zh-CN catalog, and a
  catch-all route (`routes/not-found.tsx`) makes the root loader run for unknown URLs too.
- Switching language (`LocaleSwitcher`) writes the cookie and revalidates the root loader.

## Adding a language

Add it to `locales` in `lingui.config.ts`, to `LOCALES` and `isLocaleId`/`fromAcceptLanguage` in
`app/lib/locale.ts`, and to `CATALOGS` in `app/lib/i18n.server.ts` (a type error until you do).
